# Offline Notes Search Engine

An offline, Python-based search engine that helps students quickly find relevant information in their study notes without requiring an internet connection.

## 📌 Project Overview

The Offline Notes Search Engine searches through text files stored in a local folder and displays relevant documents based on the user's query. It supports keyword searching, exact phrase searching, and all-words searching.

The project also implements an **inverted index** to improve repeated-search performance and compares indexed searching with the traditional scan-based approach.

## 🎯 Objectives

- Search local study notes without an internet connection.
- Retrieve relevant documents based on user queries.
- Support multiple search modes.
- Rank results according to relevance.
- Display useful text snippets from matching documents.
- Maintain recent search history.
- Compare scan-based searching with inverted-index searching.

## ✨ Features

### 1. Keyword Search
Finds documents containing at least one of the query words.

### 2. Exact Phrase Search
Finds documents containing the exact query phrase in the same order.

### 3. All Words Search
Finds documents containing every distinct word in the query.

### 4. Relevance Ranking
Ranks matching documents according to the search implementation's relevance-scoring method.

### 5. Text Snippets
Displays relevant portions of matching notes to help users identify useful information quickly.

### 6. Recent Search History
Keeps track of recent searches using local application data.

### 7. Inverted Index
Maps words to the documents containing them, allowing the application to narrow down candidate documents during supported searches.

### 8. Performance Comparison
Compares scan-based searching and indexed searching across repeated queries.

### 9. Offline Operation
Searches local text files without requiring an internet connection.

## 🧠 Algorithms and Data Structures

### Scan-Based Search

The application examines documents in the notes folder and checks their contents against the query.

### Inverted Index

The inverted index stores a mapping between each word and the documents containing that word.

Example:

```text
database → {dbms.txt}
python   → {python.txt}
```

This allows supported searches to identify candidate documents without scanning every document for every query.

### Performance Evaluation

The application runs repeated searches using both approaches and compares their execution times. Index construction should be considered separately when interpreting the results.

## ⏱️ Complexity Analysis

Let:
- `D` be the number of documents.
- `T` be the total number of words across all documents.
- `Q` be the number of query words.

| Operation | General complexity |
|---|---|
| Build inverted index | O(T) |
| Scan all documents | Depends on total text size |
| Look up query words in the index | Approximately O(Q) dictionary lookups, excluding result processing |
| Process candidate documents | Depends on the number and size of candidates |

Actual performance depends on document size, query terms, index construction, and system conditions.
